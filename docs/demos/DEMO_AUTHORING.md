# Authoring a guided demonstration

Start with one question the viewer can answer from public inputs. Choose an existing engine or
calculation; do not implement another financial formula inside a demo adapter.

A `Spec` records id, title, purpose, domain, difficulty, duration, concepts, prerequisites,
environment, evidence builder and flagship status. `Evidence` adds deterministic configuration,
ordered moments, limitations, verification and an optional genuine journal. The initial state is
the first moment's `before` point. Expected events, explanation references, optional questions
and named captures are recorded on each `Moment`. Recap definitions and professional uses come
from the central concept registry, so the demo does not maintain a competing explanation copy.

1. Add a unique catalogue row with existing Phase 12 concept IDs. Prerequisites are drawn from
   that registry and are suggestions, not a gate that blocks beginner access.
2. Declare seed, data provenance and model inputs **before looking at outcomes**.
3. Instantiate a detached approved session, or call an existing controlled calculation.
4. Capture a public `before`; execute the documented instruction; capture the genuine `after`.
5. Raise on an engine rejection or failed verification. Never replace it with a convenient result.
6. Use a `Question` with the existing tutor concept/validator. The question's prompt, context and
   hints must not read the `after` point, an unseen signal, scenario configuration or future rows.
7. Keep public narration honest about information and evidence quality. Put private details in
   the separately gated observer payload, never in the pre-event title or selector.
8. Add tests for the engine result, reset, no-future public response, source labels and useful links.

Shared walkthroughs are intentional: VWAP, depth, slippage and integer ticks can inspect the same
matching-engine episode. The selected topic changes the central concept focus and journey;
there is no need to manufacture a separate market for every concept. Typical reading time is
3 minutes for a focus lesson and 6 minutes for a flagship; actual pace depends on the learner.

## Four depths

Quick shows the short demonstration with an optional collapsed prediction. Learn opens
checkpoints and permits eligible grading. Quant opens maths and exposes assumptions. Interview
adds a project-defence prompt. All four inspect identical engine evidence.

For a branch, call the real engine with the chosen instructions. The delta example uses the
existing full hedge, a nearest whole-unit half hedge, or no initial hedge; all then encounter the
same prescribed market step, full rehedge and IV-input shock. Do not scale a displayed P&L curve.

## Export and review

Declare stable capture names, export after recap or explicit showcase entry, and retain the
limitations in the script. A demo path export records instructions and branch choice plus the
result digest. It is a presentation audit, not a substitute for the native financial journal.
Personal-session imports still use the original journal verifiers.
